# CRM 咨询文档结构

根据用户目的选择结构，不以固定章节数量衡量完整性。篇幅应与决策重要性、证据数量和受众匹配。

## 1. 完整业务域咨询文档

推荐核心结构：

1. 执行摘要与核心判断；
2. 业务域定位、范围和端到端关系；
3. 业务目标、利益相关方和成功标准；
4. As-Is 现状、证据和业务影响；
5. 问题树、根因和优先级；
6. 设计原则、选项和关键取舍；
7. To-Be 流程与关键业务场景；
8. 组织责任、业务规则、数据、系统和集成；
9. KPI Tree、治理、反馈与采用；
10. 差距、路线图、风险、价值和下一步。

按需增加专题包：状态机、SLA、评分、分配、审批、定价、合同条款、主数据、同意、渠道结算、服务备件、预测、集成或数据迁移。

## 2. 现状诊断报告

适用于用户问“当前哪里有问题”“如何改进”：

1. 诊断范围和证据来源；
2. 结论摘要；
3. As-Is 业务链路；
4. 关键问题和业务影响；
5. Issue Tree 与根因；
6. 成熟度或差距矩阵；
7. 改进建议；
8. P0/P1/P2 优先级；
9. 下一步验证和行动。

## 3. 业务蓝图

适用于项目蓝图、方案设计或系统建设：

1. 蓝图目标、原则和范围；
2. 端到端业务架构；
3. To-Be 流程与场景；
4. 组织、角色和 RACI；
5. 规则与决策矩阵；
6. 业务对象和概念数据模型；
7. 系统能力地图；
8. 系统边界与集成；
9. 权限、审计与治理；
10. KPI 与运营机制；
11. 实施范围、优先级、依赖和路线图。

蓝图描述“需要什么业务能力和机制”，除非用户指定产品，不直接写成厂商配置说明。

## 4. 既有文档审校

先保留用户原文意图，再输出问题矩阵：

| 优先级 | 位置 | 当前表述/设计 | 问题 | 业务风险 | 修改建议 |
|---|---|---|---|---|---|

审校至少检查：

- 生命周期状态、资格、归属、审批等概念是否混装；
- 流程是否遗漏接受、退回、异常、变更、重开和反馈；
- 规则是否有条件、责任、结果、例外和升级；
- 数据对象、字段类型、历史和审计是否支撑流程；
- RACI 是否对应关键活动和决策；
- KPI 是否形成层级、口径一致并驱动管理行动；
- 行业数据是否有来源、日期、范围和口径；
- “必须”“标准方案”“行业惯例”等绝对表达是否有适用条件；
- 文档是否区分学习表达、客户表达和系统实现表达。

修改优先级：

- **P0**：导致业务逻辑错误、误导决策、合规/数据风险或无法实施；
- **P1**：显著影响完整性、管理效果或跨部门协同；
- **P2**：表达、结构、示例和可读性优化。

## 5. 分层摘要与知识消化

大型材料不应继续无限扩写。可生成：

| 层级 | 典型用途 | 输出内容 |
|---|---|---|
| 一句话 | 快速记忆 | 定位 + 核心价值 |
| 一页纸 | 管理层/复习 | 目标、问题、方案、指标、路线 |
| 三分钟表达 | 面试/客户沟通 | 背景、判断、方案主线、价值 |
| 核心手册 | 项目团队 | 完整咨询逻辑和关键设计 |
| 专题附录 | 专家/实施 | 规则、数据、接口、指标字典 |

压缩不是删除关键逻辑，而是保留因果链和决策信息，移除重复解释与指标堆积。

## 6. 复杂方案案例

适用于面试、案例库或项目复盘：

1. 项目背景与业务目标；
2. 业务问题及影响；
3. 根因、约束和利益相关方；
4. 方案设计及关键取舍；
5. 实施难点、多部门协同和落地；
6. 结果、价值、复盘和后续优化。

先写业务设计复杂度，再补充必要的配置、开发、接口或数据迁移复杂度。只使用用户确认过的项目事实。

## 7. 章节写法

每个重要章节优先使用以下结构：

1. **结论**：这一节最重要的判断；
2. **证据/背景**：为什么得出该判断；
3. **业务影响**：不解决会产生什么结果；
4. **设计/建议**：建议如何做及适用条件；
5. **落地要点**：责任、规则、数据、系统、指标；
6. **待确认项**：仍需客户验证的问题。

## 8. 可视化选择

| 要表达的关系 | 推荐形式 |
|---|---|
| 端到端顺序、状态变化 | 流程图或状态图 |
| 根因与分支 | Issue Tree |
| 角色责任 | RACI 或泳道图 |
| 规则与条件 | 决策表/规则矩阵 |
| 对象关系 | 概念数据模型或关系表 |
| 现状与目标差距 | 对比矩阵 |
| 分阶段实施 | 路线图/时间线 |
| 指标层级 | KPI Tree |

图表必须帮助决策和理解，不为装饰而使用。

## 9. 输出与文件规则

- 未指定格式时在对话中输出结构化 Markdown 草案；
- 用户明确要求 HTML、Word、PDF 或其他文件时，再创建对应交付物；
- 更新既有文件前确认目标文件，保留用户已有内容和无关修改；
- 不因每轮产生新观点而自动改写知识库；
- 双语、咨询英语或学习例句仅在用户提出时增加。
