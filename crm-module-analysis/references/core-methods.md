# 核心方法论库（CRM 模块剖析的思考工具）

剖析模块时的底层思维工具与现场话术。需要展开讲解某个方法、或遇到用户混淆概念时读取本节。

## 1. 流程 = 状态机

- 流程的本质不是"一条直线"，而是**状态集合 + 状态转移规则 + 终止态**
- 一条完整流程有**两个终点**：成功终点（已转换）+ 失败终点（已关闭/已终止）——只有推进、不允许关闭的流程是不完整的，会导致数据永远停在中间状态（"僵尸记录"）
- **关闭不是末尾的阶段，是贯穿全流程的退出分支**：任何节点都可能关闭，每个节点的关闭原因不同（线索域：MCL 阶段多为数据质量问题、MQL 阶段是评分模型反馈、SAL 阶段是销售判定、SQL 阶段是高价值流失）
- 现场一句话："流程画不出状态转移，就不是流程，是流程图。"

## 2. 双维度正交思维（最核心的架构工具）

**识别被"混装进一个字段"的概念对，拆成正交双维度。**

线索域已验证的案例：

| 概念对 | 维度 A（回答） | 维度 B（回答） | 变化速度 |
|---|---|---|---|
| 状态 × 池子 | 线索到哪了（生命周期/资格） | 线索归谁（归属/关系） | 状态慢、池子快 |
| 状态 × 认领状态 | 值不值得跟、走到哪 | 分给谁了、人动了没 | 认领随动作瞬时 |
| 热度 × 优先级 | 多快必须动（SLA 时限） | 值不值得动用最好资源（给谁跟/跟多深） | 热度天级衰减、优先级季度级 |
| 生命周期 × 验证阶段 | 现在在发生什么（跟进中/培育中） | 被验证到哪一层（MCL/MQL/SAL/SQL） | 验证只升不退 |

**判据三问**（任一为"是"就必须分字段）：
1. 两个概念回答的问题不同吗？
2. 变化速度不同吗？
3. 由不同的人/系统决定吗？

**现场金句**：
- "两条 Hot 线索，一个 500 万一个 5 万，先跟谁？"（立住优先级）
- "分配是系统的承诺，认领是人的行动。"（立住认领状态）
- "状态管'到哪了'，池子管'归谁'——两件事，两个字段。"

**进阶设计（验证阶段）**：验证阶段不要做成销售手动维护的字段，做成**事件自动写入的履历**（评分过线自动写 MQL、销售接受自动写 SAL）——本质"验证阶段不是状态，是验证事件日志的汇总"。既无双字段维护负担，又天然留存历史，还防刷（销售改不了验证阶段）。

## 3. 规则五要素 + 每节点四类规则

**规则 = IF（条件）+ THEN（动作）+ WHEN（时限）+ WHO（责任人）+ APPROVE（审批）**

现场诊断法：拿任何一条规则问客户五要素能否说全——缺任何一项，这条规则就无法落地实现（工作流写不出来）。

每个节点的规则分四类：
- **准入规则**：凭什么进本节点（如"状态=MQL 且无归属冲突"）
- **节点内规则**：本节点内如何流转（路由优先级、防囤积、重复触达限制）
- **退出规则**：凭什么去下一节点 + 去向（下一节点/退回上游/关闭）
- **审批规则**：什么动作需要审批、谁审批、什么阈值触发

落地形态映射：字段校验（准入）→ 工作流（节点内/退出）→ 审批流（审批）→ SLA 策略（时限）。

## 4. SLA 四要素

**SLA = 计时起点 → 达标动作 → 分层时限 → 超时后果**，缺一不可。

- 计时起点：什么事件触发倒计时（如"分配到人"）
- 达标动作：什么算达标（如"首次有效触达"——注意有效触达 ≠ 拨号，要有沟通记录佐证）
- 分层时限：按热度分层（Hot ≤15min / Warm ≤4h / Cold ≤24h）
- 超时后果：升级链（先打给该节点的 A，再逐级上抛）+ 自动动作（回收重分配）

**没有超时后果的 SLA 是纸面 SLA**（对应问题库 D2）；SLA 超时后果的承接人 = RACI 里该行的 A。

## 5. 阈值回测校准法（阈值不是拍脑袋定的）

五步：① 取样本（过去 12-18 个月全部已处理记录，1000+ 条，**必须含成功样本**）→ ② 回打分（**只能用当时可得的字段**，不能用工单事后信息，否则回测全假）→ ③ 画分布（分数 → 成功转化率曲线）→ ④ 找拐点（曲线断崖处 = 候选阈值）→ ⑤ 产能校准（阈值太高没人干、太低被淹没，按产能反推总量）。

- 权衡：阈值上移 → 精准率↑、召回率↓
- **季度重校**：产品/市场/客群变了，阈值就该变
- 现场可接的话："你们这个 MQL 阈值是拍出来的还是测出来的？"

## 6. KPI 体系（六维 + 统计价值 + 维度型）

**六维覆盖检查**：量（有多少）/ 率（转化多快）/ 速（多快完成）/ 质（质量如何）/ 钱（成本与回报）/ 健康（僵尸、账龄、合规）——漏斗视角只有前三维，咨询价值要补后三维。

**统计价值两层**（每个 KPI 都要答）：
1. 回答一个问题（发现问题）
2. 驱动一个决策（解决问题）
答不出问题、推不动决策的指标 = **vanity metric（摆设指标）**。

**维度型 vs 汇总型**：
- 关键指标必须按维度拆开算（分子分母限定同一维度：渠道 A 的赢单数 ÷ 渠道 A 的线索数）
- 汇总数 = 加权平均，只当公司基线，不当答案
- 前提：归因规则先定（首触/末触）
- 现场金句："客户报整体转化率 10% → 追问哪个渠道 10%？哪个渠道 2%？——汇总数掩盖方差。"

**防刷四条纪律**：时间戳是前提（认领时间/首次触达时间分开记）、中位数优先（平均值被极值拉平）、执行类指标不挂钩提成（否则诱发假触达刷数据）、分母口径先统一（"What's the denominator here?"是现场必问句）。

## 7. RACI 纪律

- **行维度跟随流程节点**，不是按活动类型分组——客户拿到 RACI 的第一用法是"顺着流程查这个环节该找谁"
- 每行**有且只有一个 A**：一行多 A = 没人负责；SLA 超时后果的承接人就是该行的 A
- 跨节点治理项（定义/SLA 规则/监控/复盘）单独小表，标注覆盖节点——"流程表管事在谁手上，治理表管标准归谁定"
- 诊断用法：访谈画出 As-Is（各角色认知版，往往互相矛盾）vs To-Be（目标版），差距 = 治理层交付清单
- 典型失效症状：一行多 A、A 都挂在高层、执行行缺 A
- A 落位设计要点：MQL/SQL 定义 A 在销售 VP（联合 owned 销售最终问责，只压营销必打架）；认领 SLA 的 A 在主管不在本人（板子打在主管身上才有动力管）

## 8. 关闭原因码哲学

- **关闭原因 = 对上一环节的打分**：每个阶段的关闭原因，都是对前一环节质量（评分模型/销售判定/渠道质量）的反馈
- 原因码三类标准：无效类（数据问题）/ 无需求类（→休眠池）/ 流失类（→休眠池带触发条件）+ 特殊两类：合规排除（→排除池）、误关闭（Re-open）
- 四纪律：原因码必填（不允许空白关闭）、权限控制（防止"洗数据"乱关）、关闭 ≠ 删除（可逆）、关闭后自动分流
- 诊断三指标：原因码填写率（<90% = 没落地）、"其他"占比（原因码体系设计失败）、重新激活率（过高 = 关闭标准过松或乱关）

## 9. 池子设计原则

- **命名自带准入/出准语义**：待处理池（在加工）/ 公海池（等人认领）/ 私有池（有主在跟）/ 培育池（等升温）/ 休眠池（可复活）/ 排除池（黑名单）——看到名字就知道内容物状态
- 客户现有池子叫"线索池 A/B"→ 诊断发现：池子没有按生命周期语义命名 = 系统倒逼出来的设计
- **培育池只养"对的人、时机不对"**（Fit 高、Intent 低）；Fit 本身不符 ICP 的线索不进培育池，直接关闭——培育不对的人是烧钱
- 回退语义：退回公海 = 回到起点等人；退回培育 = 回到营销手里等升温——共同点是释放销售归属

## 10. 归属与认领三态

- 分配是系统动作（承诺），认领是人的动作（行动）——自动分配解决不了"人动不动"
- 认领状态三态：未分配 / 已分配·未认领 / 已认领（"已分配"和"未认领"是同一状态的两个名字，真实三态不是四态）
- 认领两种形态：显式（点按钮）/ 隐式（首次有效触达自动翻转，触达时间戳=证据）
- 认领 ≠ 资格升级：认领只是"接手了"，资格升级（如 SAL）要等跟进后判定——否则 MQL→SAL 接受率恒等于 100%，销售反馈回路断掉
- 防刷三招：假认领（要求认领后 N 小时内必须有效触达佐证）/ 占坑（设最短持有期，无活跃自动回收）/ 退回再抢（退回记录+原因码+短期禁重认领）

## 11. 一页价值故事模板

总纲句式："客户买的不是 XX（软件），是 YY（增长的确定性）。"

五条价值结构（前 3 条是钱，后 2 条是组织能力）：
1. **增收**：同样的量做出更多单（端到端转化率提升，行业 2.9% → 顶尖 6.8%）
2. **抢速**：速度本身就是赢单率（5 分钟 vs 47 小时首响）——"响应慢丢掉的单，从来不会出现在报表里"
3. **省钱**：把预算从假便宜挪到真出单（按全链路成本算渠道，CPL 便宜 ≠ 便宜）
4. **看清**：从感觉到归因（不可见业务 → 可见数字 → 可执行决策）
5. **协同**：消灭跨职能交接扯皮（定义联合签字 + 双向 SLA = 内部契约）——不直接产生钱，但决定前四条能否持续

ROI 算例规则：**只动一个保守假设**，结论足够震撼且无法反驳。模板："现状 N 条×率×率×客单价 = X 单/月；只把中间一个率提到 Y（远低于优秀线）：= Z 单/月；+Δ 单/月 = +Δ 万/月，其中一半来自零成本动作。"

## 12. 概念区分模板（易混概念对）

| 概念 A | 概念 B | 一句话区分 |
|---|---|---|
| ICP（理想客户画像） | Persona（人物画像） | ICP 管"值不值得"，Persona 管"怎么触达"；ICP 是公司级，Persona 是人级 |
| CPL（单线索成本） | Cost per SQL | CPL 是入口标价，真实成本要顺着漏斗折算到商机层 |
| 热度（Hot/Warm/Cold） | 优先级（P1-P3） | 热度管"快不快"，优先级管"值不值得动用最好资源" |
| 状态 | 池子 | 状态管"到哪了"（生命周期），池子管"归谁"（归属） |
| 业务目标 | 管理价值 | 目标是 Why（业务层），价值是 What 的变化量（管理层，可量化） |

## 13. 咨询英语配套规范

- 每节 3-5 句，两类：**现场可用句**（客户会说的话/你要说的话）+ **关键术语句**（定义式）
- 用户英语 A2-B1：中文讲解 + 大量自然英文例句 + 温和纠错，例句要短、要能直接套用
- 高频必备句：
  - "What's the denominator here?"（分母是什么——现场必问句）
  - "Break it down by channel — the aggregate number hides the variance."（按渠道拆开算——汇总数掩盖方差）
  - "Every business rule must state its trigger, action, timeline, owner, and approval."（规则五要素）
  - "Assignment is a system action; claiming is a human action."（分配≠认领）
  - "Is this account a fit for our ICP?"（是否符合理想客户画像）
