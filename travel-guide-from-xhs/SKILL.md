# Travel Guide From XHS

## Overview

把「小红书博主经验 + 实时价格查询」整合成一份可执行的旅行攻略文档。核心能力是**免登录读取小红书笔记**（包括多图笔记：从 SSR 源码提取全部图片 URL 后逐张识别），配合搜索引擎做交通/住宿/签证价格验证，最后产出结构化 HTML。进阶能力：**读取笔记评论**（博主没说但很有用的信息常藏在评论区——如「今天去人多吗」「这家店还在吗」「周一闭馆」，需要用户提供登录 cookie，见 Step 4 评论小节）。本 skill 也独立适用于「帮我读取/总结这几篇小红书笔记」类请求。

## 工作流决策树

用户提出旅行计划/攻略需求时，按以下顺序执行：

1. 需求澄清（先问再查，一次性问清关键变量）
2. 目的地调研 + 价格查询（大交通/住宿/签证/政策证件/季节天气/内部交通/门票）
3. 收集小红书笔记（用户提供的链接最优先）
4. 抓取小红书内容（核心技巧：免登录 SSR 提取）
5. 逐图识别 + 跨来源整合
6. 输出 HTML 攻略并 present_files 预览

若用户只要求读取小红书链接做总结（不一定是旅行），直接进入 Step 3–5。

## Step 1: 需求澄清

用 AskUserQuestion 一次性确认关键变量，不要逐条追问：

- **目的地**：多选时明确取舍（如「武汉 vs 日本，二选一还是都去」；都去通常行程过赶，提示利弊）
- **出发城市**：必须精确，决定航班/高铁查询方案（提示：相邻枢纽城市出发可能大幅省钱，如深圳 vs 香港）
- **同行人数**：决定住宿房间数与人均/总预算口径
- **预算档位**：经济省钱 / 舒适均衡 / 品质享受
- **签证情况**：涉及出国必问（是否有签证、能否及时办理、预算内是否接受），评估时效可行性
- **出行日期与天数**：尽量从用户消息中提取，缺失则问
- **行程节奏偏好**：打卡式 / 均衡型 / 深度轻松型——决定每日景点密度与换房频率；用户常自带约束（如「不想多坐车」「要深度」），务必捕获并让它主导行程骨架
- **交通方式偏好**：自驾 / 包车 / 公共交通 / 飞机衔接——大区域目的地直接决定骨架（如新疆用飞机切大区间）；游客常对"一天坐车几小时"有底线，先问清

一次 AskUserQuestion 最多 4 问，问题多则分两轮，先问最关键的目的地/出发城市。

## Step 2: 目的地调研 + 价格查询

用 WebSearch 查实时价格与政策（标注「查询日期 + 以下单时平台实时报价为准」，不要把搜索到的旧价当铁价）：

- **机票**：`[出发城市] 直飞 [目的地] 机票价格 [日期段] 往返`；旺季（国庆/春节）对比周边枢纽出发地，往往便宜一半以上
- **高铁**：`[出发] 到 [到达] 高铁 二等座票价 历时`；并提醒 12306 提前 15 天开售、给出开抢日期与候补建议
- **酒店**：`[城市] [核心地段] 酒店价格 每晚 人民币 [日期]`
- **签证**（涉及出国）：`[城市] 办理 [国家] 签证 费用 出签时间`，核对领区与材料时效能否赶上出发日
- **政策与证件**：`[目的地] 边防证/通行证/预约 办理`；预约制景区查放票时间与渠道（如省博每天 17:18 放票）；有电子办证渠道时给出小程序名与流程（如新疆边防证 12367 小程序，10 分钟出证）
- **季节天气与装备**：`[月份] [目的地] 天气 温差`，得出穿衣与装备清单；高海拔目的地（西藏/云南/川西等）查海拔、防晒与高反提示
- **目的地内部大交通**：大区域目的地查内陆航班/火车班次与价格（如 乌市↔喀纳斯、乌市↔伊宁，¥400-750）；内陆航班常为季节性航线，提醒尽早订
- **景区门票 + 区间车**：`[景区] 门票 区间车 价格 [旺季]`；旺季门票+景交是预算大头（如喀纳斯 ¥230 含区间车、观鱼台 +20）

## Step 3: 收集小红书笔记

目标：拿到一批目标笔记 URL 作为输入。**小红书的站内搜索在本 skill 的默认运行环境（机房/服务器 IP）下不可用**：搜索 API 需登录（`-101`）、搜索页会被 IP 风控重定向（`300012`）。因此按以下来源获取链接：

1. **用户主动提供的笔记链接**（最可信）→ 直接进入 Step 4 抓取
2. **用户提供关键词时**：WebSearch 搜 `小红书 [目的地] [X天X晚] 攻略`，从转载站（今日头条/腾讯/新浪/百家号等）提取信息作补充证据——转载站通常拿不到原帖链接，但内容可用；若转载文中提到博主昵称/店铺名，可提示用户去小红书搜「博主名」获取原帖
3. 用户可在自己的小红书 App/网页里搜索，把链接批量发来（`xhs_fetch.py` 支持 txt 文件批量）

**收到多篇笔记时，用热度排序决定读取优先级**：笔记页 SSR 里带免登录可读的 `interactInfo`（收藏数 > 点赞数 > 评论数，见 references）。可先快速抓取所有候选笔记页的 HTML，解析出收藏/点赞数排序，优先逐图读取高收藏的笔记（收藏代表「照着能用」，攻略价值最高），低热度笔记只扫正文不细读。

## Step 4: 抓取小红书笔记内容（核心）

**先试 WebFetch** 直接抓链接；失败（登录墙/空壳）是常态，不要停在失败上，直接走 SSR 提取路线。

免登录提取路线（**不要**优先用浏览器自动化——机器出口 IP 是机房 IP 会被小红书风控拦登录）：

1. curl 带浏览器 UA 下载笔记 HTML：`curl -s -L -A "<浏览器UA>" "<笔记URL>" -o note.html`
2. 提取 `window.__INITIAL_STATE__` 的 JSON，做 `unicode_escape` 反转义（图片 URL 的斜杠是 `\u002F` 转义的）
3. 正则提取全部 `xhscdn.com` 图片 URL（结尾 `!nd_dft_wlteh_jpg_3`）
4. Python urllib 带 `Referer: https://www.xiaohongshu.com/` 批量下载全部图片
5. 用 Read 工具逐张识别图片文字（当前模型可直接读图）

**直接运行 `scripts/xhs_fetch.py` 可一键完成步骤 1–4**：传入笔记 URL（支持 txt 文件批量），自动下载页面 HTML + 全部图片到 `xhs_imgs/`。

⚠️ **控制抓取节奏**：批量抓取时每篇间隔 2-5 秒，单次别超过 5-10 篇；密集请求会触发临时 IP 风控，SSR 内容会整体失效（返回 34KB 登录墙页、`noteDetailMap` 为 null）。遇到这种情况停手等待风控冷却（数小时到一天），不要重试。

原理、正则细节与故障排查见 `references/xhs-note-extraction.md`。

### Step 4.5: 读取评论（可选，需登录 cookie）

评论区常有博主没写的信息（实时人流量、店铺是否还在、临时避坑补充），值得抓取。**注意：评论接口必须登录态 cookie，无法匿名读取**：

- **已实测结论**：`edith.xiaohongshu.com/api/sns/web/v2/comment/page` 需要 x-s/x-t/x-s-common 签名头 **且** 登录 cookie。无 cookie 时返回 `code -101「无登录信息，或登录信息为空」`；SSR 笔记页 HTML 里的评论字段是空占位（list 为空）。
- **签名来源**：用 Playwright + 系统 Chrome 加载任意笔记页，等页面里的 `window._webmsxyw`（XHS 当前签名函数）就绪，抓取页面启动请求里的 `x-s-common`，再从页面内发起 API 请求（`credentials: 'include'`）。
- **环境硬性要求**：评论接口对登录态校验很严。**机房/Cloudflare WARP/服务器 IP 环境会被风控识别**，即使拿到 cookie，也容易触发 `300011 当前账号存在异常`、随后 `web_session` 被吊销（`-100 登录已过期`）或直接被删除（`-101 无登录信息`）。因此脚本**必须在与账号匹配的家庭宽带/手机流量/办公室网络环境下运行**；若当前执行环境是机房 IP，只准备脚本/传文件，不要实际调用。
- **cookie 获取方式**：请用户在自己已登录的浏览器里复制 cookie（DevTools → Application → Cookies → www.xiaohongshu.com，至少需要 `a1` + `web_session`，或整站 cookie），通过 `XHS_COOKIE` 环境变量或 `--cookie-file` 传入。`web_session` 是 Session cookie，关闭浏览器或触发风控后会失效，建议每次使用前现取。
- **运行**：`python scripts/xhs_comments.py <笔记URL>...`（支持 txt 批量），输出到 `comments/<note_id>.md`（含昵称、点赞、正文、时间，楼中楼子评论缩进显示）。
- 错误码速查：`-1` 签名失效；`-101` cookie 缺失/被删除；`-100` cookie 过期/吊销；`300011` 当前账号异常（IP/环境风控，立即停手换网络）。
- 评论是「用户反馈」级别的信源，整合时标注「来自评论区」，与笔记正文、实时查询交叉验证；对「某店今天开门吗」「排队要多久」这类时效信息，评论时效往往好于正文。

## Step 5: 逐图识别 + 整合

- 按笔记逐张 Read 图片，转写每张图的文字/评分/避坑点；用 TaskCreate 按笔记建任务，读完一张标记进度，避免漏图
- 整理成结构化要点：景点推荐度/评分、美食清单、避坑点、预约/放票时间、交通细节、住宿建议
- 若用户提供了登录 cookie：顺手跑 `scripts/xhs_comments.py` 抓评论，重点找评论区补充的时效信息（人流、排队、临时闭馆/闭店、价格变动），作为低优先级证据并入要点（标注「评论区」）
- 与已有计划交叉验证：重复信息去重，冲突信息取多数来源，缺来源的信息标注「来源待确认」
- 转写结束后清理临时 HTML 文件，保留 `xhs_imgs/` 供溯源

## Step 6: 输出 HTML 攻略

产出单文件 HTML（无外部依赖、双击即开），推荐章节结构：

- 头部：标题、日期、人数/预算档位标签
- 交通方案（含 12306 开抢日期提醒）
- 住宿策略（地段对比、分区住 vs 单点住）
- 逐日行程（每日主路线 + 雨天备选 + 晚间二选一）
- 美食总清单（按过早/正餐/小吃甜品分类，标注来源）
- 预算明细表（按 2 人计 + 单人换算）
- 行动时间线（购票/预约/放票时间点）
- 避坑清单
- 参考来源表（小红书笔记链接可点击直达）
- 可选章节：**装备/气候清单**（温差大或高海拔目的地必加：温差区间、必带衣物、防晒/高反提示）；**政策与证件**（边防证办理流程、景区预约放票规则）

多方案对比时，先给一张「对比总表」（大交通/签证/总预算），让用户拍板再细化。完成后用 present_files 打开预览。

## 大区域目的地专项（新疆/西藏/内蒙/云南/东北等）

面积大、景区分散的目的地，行程骨架与城市游不同：

- **用飞机/高铁切大区间，避免每日车程过长**：用户常提「不想多坐车」——方案里优先"飞进飞出"核心景区（如 乌市↔喀纳斯 直飞），把长车程换成长途航班，把时间留给游玩
- **内部交通尽早订**：内陆支线航班多为季节性航线（班次少、涨价快），确认行程后第一时间提醒下单
- **边境/通行政策**：部分区域需要边防证（如白哈巴、独库部分路段周边），查清适用景区、办理渠道（小程序）与目的地填写口径，写进攻略
- **季节窗口倒排行程**：赏秋/赏雪/花季/避暑各有最佳时间窗（如 9 月中下旬喀纳斯禾木黄叶），按窗口确定去核心景区的日期，再往两头排
- **装备落地**：给出具体温差区间（如白天 18-23 / 夜间 0-5），必带衣物点名，防寒/防晒/高反按需提示
- **单日车程红线**：单日车程超 4 小时时，提示可拆分成两段或改乘飞机

## 交付后

- 提示用户：机票/酒店价格随日期浮动，锁定方案后尽快下单
- 给出下一步行动时间线（抢票日、预约日、送签日）
- 若有未决项（如两个方案选哪个），明确等待用户拍板
- 若有来源不确定的信息，主动坦承（如「这篇我只读到封面图」），不要假装读全
